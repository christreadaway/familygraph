Posture vocabulary.

Five states a piece of family data can be in. Every one has a pill, a hue, and a rule for when it appears. The operator never has to ask "is this safe to share."

LOOPBACK
Bind is 127.0.0.1 — nothing reaches the network.
Status rail · health endpoint · /api/safe/*
ENCRYPTED
Column ciphertext at rest (AES-256-GCM).
Field-level sigil · backups · keyfile mode
PSEUDONYM
Identifiers in place of names. AI-safe by construction.
Sanitize output · safe API · pseudonym view
PII
Real names visible. Operator session only.
Dashboard · /api/families/:code · audit
CONSENTED
PII left the machine — explicit consent + tier-2 audit.
Exports · external-export endpoint

Where posture appears

ambient signals
  • Status rail — pinned at top of every screen. Never collapsed, never hidden.
  • Field-level sigil — 5px dot beside any sensitive value.
  • Pill — at the row level (audit row, conflict row, export row).
  • Header toggle — PII ↔ Pseudonym view. Affects the whole page.

Hue policy

oklch · matched chroma
  • loopback · hue 142 (green) — your machine only
  • encrypted · hue 200 (cyan) — ciphertext at rest
  • pseudonym · hue 250 (indigo) — AI-safe
  • pii · hue 30 (amber) — real names visible
  • consented · hue 350 (rose) — left the machine

Identifier system.

Every entity has a typed prefix, a non-semantic 8-hex code, and a permanent slot in the ledger. Hue is consistent: family is always indigo, person always cyan, address always green. The operator builds spatial muscle memory: "I'm looking at a person."

f_a7b3c91d ^f_[0-9a-f]{8}$ Family · the household envelope permanent · alias on merge · transitively followed
p_e4d2f8a1 ^p_[0-9a-f]{8}$ Person · stable across family changes a child emancipating gets a new family, not a new person
addr_4c7f2a91 ^addr_[0-9a-f]{8}$ Address · dedup'd by HMAC street normalized → HMAC-SHA256 → equality
e_b91c4f23 ^e_[0-9a-f]{8}$ Email · ciphertext + HMAC no substring search; equality only
ph_2d8a5e91 ^ph_[0-9a-f]{8}$ Phone · ciphertext + HMAC E.164 normalized before hash
conf_b1c2d3e4 conf_ Conflict · resolution queue row open · merged · rejected · dismissed
tk_a1b2c3d4 tk_ Token set · sanitize round-trip mappings_ct encrypted at rest
au_aabbccdd au_ Audit row · tier-1 or tier-2 tier-1 sweepable · tier-2 forever

Permanence rules

  • Codes are assigned once. Never reused, never reissued.
  • On merge, loser's code becomes a permanent alias of the winner.
  • Person codes are stable across family-membership changes.
  • Family codes do not change when household composition changes.

Display rule

.fg-code.family   { color: oklch(58% 0.12 250); }
.fg-code.person   { color: oklch(58% 0.12 200); }
.fg-code.address  { color: oklch(58% 0.12 142); }
.fg-code.email    { color: oklch(58% 0.12 90); }
.fg-code.phone    { color: oklch(58% 0.12 30); }
always JetBrains Mono · no underline · no link unless hover

Native chrome. Identical content.

Family Graph runs on macOS and Windows. The window controls defer to the OS — traffic lights on Mac, min/max/close on Windows — so the app feels at home on each. Everything below the title bar — the status rail, the header, every layout, every pill, every glyph — is pixel-identical.

What's native

defer to the OS
  • Title bar & window controls. Set decorations: true in Tauri. macOS draws traffic lights on the left; Windows draws min/max/close on the right.
  • Window dragging. Free — the OS handles it. No -webkit-app-region: drag needed.
  • Snap, fullscreen, mission-control. All native gestures work because we don't override the frame.

What's identical

brand-owned, edge to edge
  • Status rail (32px, loopback / encrypted / audit). The first row of pixels inside the window. Same on both OSes.
  • All content below it — header, posture pills, identifier hues, provenance dots, conflict rows, audit feed, scrollbars. Pixel-diff and they match within 1px.
  • Fonts. Inter, Inter Tight, JetBrains Mono — bundled as WOFF2, never CDN, never system fallback.

Per-OS refinements

// macOS — flush the rail under the traffic lights
#[cfg(target_os = "macos")]
window.set_title_bar_style(TitleBarStyle::Transparent)?;

// Windows 11 — tint the OS caption bar to match
#[cfg(target_os = "windows")]
window.set_decorations_color("#f5f6f8")?;

// CSS — set once at boot
:root[data-platform="mac"] .fg-rail { padding-left: 84px; }
:root[data-platform="win"] .fg-rail { padding-left: 14px; }

Pixel parity gotchas

  • Windows DPI. Defaults to 100% but renders at 125% / 150% on many displays. Test all three. 0.5px borders may need a 1px fallback at <2× DPI.
  • Scrollbars. Force the custom 8px thumb everywhere — Windows default is 17px and breaks rhythm.
  • Font smoothing. Set -webkit-font-smoothing: antialiased + -moz-osx-font-smoothing: grayscale globally; documents intent on both OSes.
  • OKLCH. Chromium 111+ supports it natively (Tauri/Electron are fine). For PDF exports, resolve to hex at build time.

Implementation handoff.

Engineering reads CLAUDE_CODE_HANDOFF.md first. It contains the full token export, file layout, component contracts, and the "do this, not that" rules that won't be obvious from reading the existing dashboard.

Files in the handoff package

  • CLAUDE_CODE_HANDOFF.md — implementation spec (this is where engineering starts)
  • tokens.css — drop into client/src/styles/
  • shared.css — component classes (atoms)
  • overview.jsx — reference implementation of Home / Overview screen
  • fg-data.js — fixture data shape (mirrors API responses)
  • Family Graph — Institutional Design System.pdf — this document, for reviewers

Migration path from current dashboard

  • Step 1. Add tokens.css + shared.css alongside existing styles. Set data-theme="institutional" on <html>.
  • Step 2. Replace existing route shells with the status rail + header (PII/Pseudonym toggle in app state).
  • Step 3. Migrate one route at a time to the new components. Start with /conflicts (highest ROI).
  • Step 4. Configure native chrome — Tauri with decorations: true, plus per-OS refinements (transparent title bar on macOS, tinted caption on Windows).
  • Step 5. Bundle fonts. Remove CDN font links. Verify on Windows + macOS.

What the handoff does NOT include — explicit non-goals

  • No new API surface. Use the existing /api/* routes documented in product_spec.md.
  • No new routes. Same dashboard URLs (/families, /people, /conflicts, …).
  • No icon library. Identifiers + sigils + dots replace most icons. If you need one, prefer a single text glyph (←, →, ✕) over an SVG set.
  • No animation framework. CSS transitions only (150ms ease for color, 200ms ease for layout).
  • No dark mode work — that's the Forensic theme, ship it later. Institutional is light-only by design.
  • No icon-driven empty states. Empty states are a single sentence in --ink-mute, no illustration.
For engineering — read this once.
The dashboard is a posture indicator first and a CRUD UI second. If a new feature breaks the rule "operator can see PII vs pseudonym vs consented at a glance," push back before merging. Posture is the product.
