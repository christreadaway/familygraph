Situation

School rosters and parishioner lists are about to run through Doc Anonymizer so AI can work on them safely. Without a shared identifier, the same mother would get a different code in every file, and nobody could tell that "Maria Garcia" on the parish list and on the school roster is one person. MissionIQ already holds most of the community, some of it linked by a looser matcher.

What we did

  • Made Family Graph the only system that issues IDs, and gave its codes a readable form: I + 16 hex for a person, F + 16 hex for a family.
  • Built a one-time, read-only MissionIQ import that links every MissionIQ record to its Family Graph person, so later lookups are exact, not guesses.
  • Connected Doc Anonymizer to Family Graph for spreadsheets: names become IDs, questions appear in the preview, and nothing is written until you confirm.
  • Rewrote matching so obvious cases settle on their own in both directions, and only real ambiguity reaches a person.
  • Locked it down: everything stays inside the firewall, every data call needs a scoped key, and logs hold counts, never names.
  • Ran an independent bug hunt: 40 defects fixed, plus 10 caught reviewing the fixes.

Results

  • 10 of 1,289 people needed a decision on the MissionIQ import; a re-run needed 0.
  • 0 wrong matches and 30 questions (1 in 33 people) on a 500-family roster; before the rework it was 884 questions.
  • Fixed old matcher bugs that could merge spouses or neighbors.

What's next

  • Upgrade Family Graph on the Spark server, then run import-missioniq once, answering its few questions.
  • Connect MissionIQ with a key named missioniq and press Sync now once.
  • Anonymize the first real roster and keep the key file in the backup routine.

The system map

Three products, one identity registry, one firewall

Family Graph is the registry: it alone decides whether someone already exists and issues IDs. MissionIQ and Doc Anonymizer ask it; they never mint an identity of their own.

Who owns what

  • Family Graph owns identity: who exists, who belongs to which household, and every ID.
  • MissionIQ owns giving and donor work. It keys that work to Family Graph IDs.
  • Doc Anonymizer owns documents. It asks Family Graph for IDs and keeps the key that restores names.

What each side can see

  • The AI model sees only anonymized text, never a real name.
  • Doc Anonymizer's key carries one scope, roster: plan and commit rosters, look up an ID. It cannot browse the directory, change settings, or delete anyone.
  • MissionIQ's file is opened read-only; nothing is ever written back into it.

The identifier

One code, two spellings, never reissued

The community ID is Family Graph's own code, written so a spreadsheet and a person can read it. Nothing is translated or stored twice.

The promises

  • One human, one ID, for life. The same mother keeps her ID on the parish list, next year's roster, and in MissionIQ.
  • Never reissued. An ID is never given to anyone else, even after the person leaves.
  • Merges redirect. If two records turn out to be one person, the old ID points to the survivor forever, so older files still restore.
  • Nothing minted on a guess. An ID is created only after every open question is answered and you confirm.
  • Retry-safe. If the connection drops mid-save, resending can never create a second ID; the file stays locked until the outcome is known.

The crosswalk

  • Each imported MissionIQ record is linked to its person: contact:<id>, child:<id>, family:<id>.
  • From then on, "MissionIQ contact X" is that person. Lookups are exact, never re-matched by name.
  • Only a deliberate import writes a link. Everyday lookups read links; they never create them, so a loose guess can never become permanent.
  • If a linked record later changes into someone else (a different first name and birthdate), it comes back as a question.

How matching decides

Automatic when it is obvious, a question only when it is not

Each incoming person is compared with everyone Family Graph knows. Three outcomes:

Same person, automatically

  • Same email or phone and the first name lines up (Lupe = Guadalupe, Bob = Robert)
  • Same first and last name and same birthdate
  • Same first and last name and same home address
  • A student listed by name only, in a household we already know
  • A MissionIQ record imported before (the crosswalk)

Different person, automatically

  • Shared inbox, different first name: a spouse or a child, not the same person
  • Jr and Sr, or II and III
  • Different birthdates, with nothing else shared
  • An adult row against a child record at one address (John and John Jr.)
  • In one upload: same-named students in different grades, or same-named parents with different emails and homes

Ask a person

  • Same first and last name, nothing to confirm or rule out
  • Same name, same inbox, different birthdate (maybe a typo)
  • Two possible matches at once
  • A stored MissionIQ link that no longer fits the record
  • The same name twice in one household
  • Look-alike first names (Luis / Luisa)
  • Placeholders ("TBD"), initials, or a business name

Running it on the Spark server

Security, logging, and the commands you will use

Security posture

  • Family Graph and MissionIQ run in Kubernetes on the Spark server, managed from HQ, and answer only on the site network. MissionIQ reaches Family Graph inside the server.
  • Every Family Graph data call needs a key. Port 30500 is plain HTTP, so keep it on a staff-only network; guest or student Wi-Fi must not reach it.
  • Doc Anonymizer runs on your Mac, answers only on 127.0.0.1, and refuses any Family Graph address outside the local network. No override.
  • Doc Anonymizer's Family Graph key carries only the roster scope. It is stored in a file only the owner can read, never shown again, never logged.
  • Contact details in Family Graph are encrypted at rest; searches use keyed hashes.
  • Uploaded files are deleted the moment processing ends or fails.

What the logs hold

  • Logged: file name, sizes, counts matched / new / asked, import run code, timings, and full error details.
  • Never logged: names, emails, phones, addresses, document text, replacement values, or keys.
  • Family Graph: server.log and cli.log under /data/logs in its pod.
  • MissionIQ: /data/logs/familygraph.log in its pod.
  • Doc Anonymizer: ~/doc-anonymizer/anonymizer.log on the Mac.
  • Paste the last lines into a chat when something breaks; they are safe to share.

Keep in the backup routine

  • Family Graph: family-graph backup <passphrase> in its pod (encrypted, lands on its volume; copy it off the box).
  • Doc Anonymizer: the keys/ folder on the Mac. Without a key file an anonymized document cannot be restored.

Known follow-ups
